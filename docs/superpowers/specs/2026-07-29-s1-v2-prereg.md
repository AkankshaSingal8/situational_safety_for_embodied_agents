## Why v1 could not answer the question

v1 criteria: median cos(approach) ≥ 0.50 (measured **0.940**, PASS) AND
cos(approach) > cos(task) on ≥ 70% of scenes (measured **0.55**, FAIL).

The failing criterion was uninformative on the scenes it ran. Median
`cos_task` was **0.954** — SafeLIBERO places the obstacle on the path to the
goal, so the task prompt already points at the hazard and there is no headroom
for the approach prompt to beat it.

| stratum | n | frac approach > task | mean Δ |
|---|---|---|---|
| cos_task ≥ 0.9 (ceiling) | 14 | 0.43 | −0.047 (noise) |
| cos_task < 0.8 (informative) | 5 | 1.00 | +0.427 |

`corr(cos_task, Δ) = −0.498`. The metric measured hazard/goal collinearity,
not steerability.

## Five defects fixed in v2

| # | defect in v1 | fix |
|---|---|---|
| D1 | scored two absolute cosines and compared them — saturates | score the **contrast** `Δv = v(approach) − v(task)`, which is what a CFG-style steering mechanism would actually use |
| D2 | `cos_xy` discarded z a priori | 3D cosine is primary; xy reported as a secondary column only |
| D3 | summed the whole action chunk, where late steps are already past the obstacle | score the **prefix** (first 5 steps = the eval client's replan cadence) as primary, full chunk secondary |
| D4 | one inference per (scene, prompt) — no noise floor, so ±0.07 was uninterpretable | 3 repeats per prompt; report across-seed sd |
| D5 | no negative control — a positive could mean "naming any object perturbs the chunk" | **decoy prompt** naming a non-hazard object in the same scene (farthest from the hazard); the hazard contrast must beat the decoy contrast |

Also: v1 persisted only scalars, so no reanalysis was possible without a
rerun. v2 saves raw displacement vectors.

## Pre-registered criteria (v2)

Scenes: `safelibero_spatial` level I, 4 tasks × 5 init states = 20 scenes.
Primary metric: `cos3(Δv_prefix, hazard_pos − eef_pos)`, per scene.

**GO requires BOTH:**
1. `median(cos3(Δv_prefix, hazard)) ≥ 0.50` across all 20 scenes.
2. `cos3(Δv_prefix, hazard) > cos3(Δv_decoy_prefix, hazard)` on **≥ 15 / 20**
   scenes (the task #36 "≥15/19" bar, restated for n=20).

**NO-GO** if either fails. **INVALID** (no verdict) if fewer than 15 scenes are
collected — v1's zero-scene run wrote a NO-GO on n=0 and that must not recur.

Reported but NOT criteria (to prevent post-hoc criterion selection):
full-chunk contrast, xy columns, `cos_task_3d`, per-scene sd, `frac_positive`,
stratification by `cos_task`.

## Honest statement of what a GO buys

A GO establishes only that **a hazard direction is recoverable from the frozen
policy by an instruction swap**, and that it is hazard-specific rather than a
generic prompt perturbation. It does NOT establish that steering along that
direction improves TSR or CAR. That conversion is the step that has failed
repeatedly in this project — visual conditioning NO-GO (2026-07-28, CAR 15.0 vs
14.0 baseline), and every steering operator statistically indistinguishable from
composed production at n=200 (Stages 1–3 + derived tilt).

Two further cautions specific to this direction:
- The C4 geometry audit (2026-07-29) shows Spatial t1's binding constraint is
  the corridor exemption, not the hazard model — a better hazard direction does
  not address it.
- The no-GT weak cells are 100% timeouts (liveness), not collisions, so a
  hazard-direction model is not obviously the lever there either.

So the value of running v2 is primarily **negative-result quality**: v1's NO-GO
currently rests on a confounded criterion, which is a weak thing to put in a
paper. v2 either yields a clean NO-GO worth citing, or a GO that justifies one
implementation attempt.
